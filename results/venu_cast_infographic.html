📊 Venu Cast — How the Forecast Model Works

From raw template upload → per-venue daily sales forecast → full P&L. Every step, every fallback, every guardrail.

FY27 model · Prophet/SARIMA/Holt-Winters/DOW-Flat · State-aware weather + holidays · Layered safety nets

1 DATA INPUTS

5 sales templates uploaded

  • XLSX 01 Sales History — 3 tabs (Servings, Retail, POS Discounts), wide format, 1 row/venue × 5+ years daily
  • XLSX ATP History — long-format ticket value per venue per day
  • XLSX D03 Location BI — cluster + cluster_type per venue
  • XLSX Venue Details — opening_date, ramp-up %, impact venues (cannibalisation)
  • CSV Venue City Mapping — 15-month multipliers per venue

2 EXTERNAL DATA (auto-fetched)

Weather + state-aware public holidays

  • API Open-Meteo Archive — historical temp_max, precipitation, wind_max, gusts_max for the state's anchor city
  • API Open-Meteo Forecast — climatology (multi-year avg per day-of-year) for future dates
  • PKG holidays Python pkg — full state-specific calendar (VIC has Melb Cup, QLD has Royal QLD Show, etc.)
  • Extreme-weather flag = (gusts ≥ 90 km/h OR rain ≥ 50 mm) → cyclone/storm marker
  • Cached per state to avoid repeated fetches

3 PER-VENUE HISTORY ANALYSIS

Profile each venue's sales pattern

  • n_trading = count of non-zero days
  • patchiness = fraction of zero days
  • stable_mean = median (robust to spikes/zeros)
  • recent_mean = mean of last 28 trading days
  • recent_max = highest single day in last 28
  • dow_means = per-weekday average (Mon-Sun)

Flags set: bypass_prophet (<21 days), is_patchy, use_flat_forecast

5 PROPHET FIT (the data-science core for mature venues)

Decomposes daily sales into trend + seasonality + regressors

y(t) = trend(t) × weekly(t) × yearly(t) × holiday(t) × temp_max × precipitation × wind_gusts × extreme_event_flag
Trend
changepoint_prior=0.010 → tight, won't extrapolate recent dips. changepoint_range=0.85 → no trend changes in last 15% of history.
Seasonality
Weekly always. Yearly with 12 Fourier terms (365+ days). seasonality_prior=30 → strong seasonal variation for beach venues.
Holidays
Per-state, named. Prophet learns per-holiday lift/dip (Melbourne Cup, ANZAC, Christmas, etc.).
Weather regressors
temp_max, precipitation, wind_gusts, extreme_event (4 standardized regressors). Climatology fills future.

6 RESOLUTION CHAIN — applied per venue, in this exact order

Each step is independent and can be toggled. The final forecast is the result of this entire chain.

0. SCENARIO OVERRIDEIf user set a per-venue scenario (target growth % or target avg daily $), it WINS — no other adjustments apply. Calibrated multiplier hits target exactly.
→
FINAL forecastUser authority preserved

— OR, if no scenario set, the model goes through these adjustments —

1. Raw Prophet outputDaily sales = Prophet fit × 15-month multiplier from CSV
→
2. SOFTENING (β=0.7 default)Shrink FY27 avg toward FY26 baseline: target=β×Prophet+(1-β)×FY26/day. Preserves daily shape, gentles the level.
3. Cluster CannibalisationIf venue is in another opener's "Impact venue" list, apply monthly impact % during opener's first 6 months. Multipliers stack.
→
4. Baseline GUARDRAILSCap FY27 within band of annualised FY26: mature 0.80–1.30×, ramping 0.75–1.30× (+recent-run-rate cap). Catches extremes.
5. UNIVERSAL LFL ADJUSTMENTPer-month multiplier scales LFL venues' streams to hit network LFL target (on basis = current Sales Type view). Skips venues with scenarios.
→
FINAL forecastSales × Multiplier × β-soften × Cann × Guards × LFL

7 DERIVED OUTPUTS

From the final daily forecast

ATP_forecast[day] = last_ATP × (1 + monthly_growth%)
Transactions[day] = Servings_forecast / ATP_forecast
Integrated_check = Transactions × ATP (should == Servings)
  • POS Discounts shown as negative values in all outputs
  • Reconciliation: integrated forecast should match direct forecast; divergences >10% flagged

8 NEW VENUE HANDLING

Future venues with no history

weekly_$ = new_monthly_sales / 4.345 weeks
daily_$ = weekly_$ × DOW_share × ramp_factor[month]
DOW_share borrowed from cluster peers (mature venues)
  • Opening date from Venue Details determines start
  • Zero sales before opening date
  • Month 1-6 ramp % from Venue Details template applies progressively
  • 15-month multiplier + ATP forecast still applied on top

9 SANITY CEILINGS (inside Prophet engine)

Hard caps applied BEFORE the resolution chain

< 28 daysCAPrecent_max × 1.5
28–89 daysCAPmax(recent_max×2, stable×3)
90+ daysCAPstable_mean × 4

Floor: 0.40 × recent_mean (for venues with 60+ trading days). Loose enough to allow legitimate winter dips for seasonal venues.

10 UNIVERSAL LFL MATH

LFL pool = venues with cohort = "FY26 Existing"
AND no per-venue scenario active

pre_LFL = sum(FY27 forecast across pool)
target = LFL_FY26 × (1 + target_pct/100)
gap = target - pre_LFL

monthly_multiplier[m] = 1 + (gap × weight[m]) / pre_FY27[m]

Target basis = current Sales Type view (servings / retail / discounts / all combined). Weights auto-normalise to 100%.
